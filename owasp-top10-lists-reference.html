01

Application design, implementation, configuration and operation.

2025OWASP list ↗

Can the application enforce its security boundaries?

Risk / official identifierSummary · what it coversIllustrative exampleKey controls
A01:2025Broken Access ControlOWASP source ↗Authorization checks fail to restrict which records, actions, or resources a caller can access. Covers horizontal and vertical privilege escalation, ownership failures, and related access-control weaknesses.A signed-in customer changes an invoice ID and reads another customer’s bill.Deny by default; enforce server-side object and action permissions; test tenant boundaries and privilege escalation.
A02:2025Security MisconfigurationOWASP source ↗Unsafe defaults, exposed administrative interfaces, excessive services, permissive settings, and inconsistent hardening leave exploitable gaps across applications and infrastructure.A production debug endpoint exposes configuration and stack traces.Use hardened deployment templates; disable unused features; protect management interfaces; continuously check configuration drift.
A03:2025Software Supply Chain FailuresOWASP source ↗Dependencies, build systems, package distribution, and release processes introduce compromised, vulnerable, or unmaintained software into an application. The risk extends beyond a vulnerable library.A compromised build dependency inserts malicious code into an otherwise legitimate release.Inventory components with an SBOM; pin and verify dependencies; secure CI/CD identities; patch and assess supplier provenance.
A04:2025Cryptographic FailuresOWASP source ↗Missing or weak cryptography, poor randomness, exposed keys, and incorrect certificate validation compromise sensitive information in transit or at rest.A database backup is encrypted, but its decryption key is stored beside it.Use approved cryptographic libraries and TLS; manage keys separately; rotate secrets; use dedicated password hashing.
A05:2025InjectionOWASP source ↗Untrusted input is interpreted as commands, queries, or executable content. Includes SQL, operating-system and other interpreter injection, plus cross-site scripting.A search parameter changes a database query instead of remaining a literal search value.Use parameterized queries and safe APIs; apply context-specific output encoding; validate input; avoid dynamic command construction.
A06:2025Insecure DesignOWASP source ↗Required security controls are absent or inadequate in the design itself. Correct coding cannot compensate for a workflow that allows fundamentally unsafe behavior.A recovery workflow resets an account using information that is publicly available.Threat-model abuse cases; define security requirements and trust boundaries; use secure patterns; test business constraints.
A07:2025Authentication FailuresOWASP source ↗Weak sign-in, credential recovery, session handling, or identity verification allows account takeover and impersonation. Authentication establishes identity; authorization determines permitted actions.A stolen session remains usable after password reset and logout.Use strong MFA; protect recovery; throttle abuse; securely manage sessions; revoke or expire credentials appropriately.
A08:2025Software or Data Integrity FailuresOWASP source ↗The application trusts software, serialized objects, updates, or critical data without sufficient verification that they are authentic and unmodified.An unsigned update or tampered serialized object is accepted as trusted input.Verify signatures and integrity against trusted provenance; protect update paths; avoid unsafe deserialization; validate critical state.
A09:2025Security Logging and Alerting FailuresOWASP source ↗Missing, incomplete, or unactionable security telemetry prevents timely detection, investigation, and response. Collecting logs alone is insufficient if meaningful alerts never reach responders.Repeated account takeover attempts appear in logs but generate no operational alert.Log identity, action, target and outcome; protect log integrity; connect alerts to response playbooks; exercise detection.
A10:2025Mishandling of Exceptional ConditionsOWASP source ↗Unexpected states, errors, and resource shortages are handled unsafely. Fail-open behavior, incomplete cleanup, and inconsistent transactions can expose data or break security controls.An authorization-service timeout causes the application to allow a request.Fail securely; handle exceptions centrally; apply timeouts and resource limits; preserve transaction integrity; test failure paths.

Access control, secure design and application logic remain essential even when WAF protection is present. A03 focuses on the supply chain; A08 focuses on integrity verification of software and data.

02

Exposed objects, properties, functions and business workflows.

2023OWASP list ↗

Who can call which operation on which object and fields?

Risk / official identifierSummary · what it coversIllustrative exampleKey controls
API1:2023Broken Object Level AuthorizationOWASP source ↗BOLA: the API fails to verify that the caller may perform the requested operation on the specific object identified in the request.Changing an order ID exposes another tenant’s order, even with a valid access token.Authorize every object access and action server-side; include tenant and ownership context; do not rely on unpredictable IDs.
API2:2023Broken AuthenticationOWASP source ↗Incorrect identity and token handling lets attackers impersonate users. Includes weak recovery, credential abuse, and inadequate validation of authentication tokens.An endpoint accepts an expired token or a token issued for a different audience.Validate issuer, audience, signature and expiry; secure recovery and sessions; protect credentials; throttle authentication abuse.
API3:2023Broken Object Property Level AuthorizationOWASP source ↗BOPLA: callers can read or modify object fields they are not entitled to access. Combines excessive data exposure and unsafe property assignment.A profile update accepts an admin flag; a response returns internal salary fields.Allowlist readable and writable fields by role; validate schemas; use explicit response models; avoid automatic mass assignment.
API4:2023Unrestricted Resource ConsumptionOWASP source ↗Requests consume excessive compute, memory, storage, bandwidth, or paid downstream services because usage and workload limits are absent or ineffective.A small number of requests triggers huge exports or thousands of billable SMS messages.Limit rate, concurrency, payloads, pagination and execution time; enforce per-identity quotas and downstream spending ceilings.
API5:2023Broken Function Level AuthorizationOWASP source ↗BFLA: users invoke operations reserved for other roles because administrative and ordinary business functions lack consistent authorization.A regular user calls a privileged bulk-delete endpoint directly.Deny functions by default; authorize every method and route; centralize role and policy checks; test privileged endpoints.
API6:2023Unrestricted Access to Sensitive Business FlowsOWASP source ↗Legitimate business workflows can be automated or repeated at harmful scale. Abuse succeeds even when each request is technically valid and correctly authenticated.Bots reserve all appointment slots or repeatedly exploit a promotional workflow.Identify abuse-sensitive flows; enforce business quotas, velocity checks and bot defenses; monitor sequences and economic impact.
API7:2023Server Side Request ForgeryOWASP source ↗SSRF: an API fetches a user-influenced URL without sufficient destination restrictions, allowing requests to internal services or other unintended locations.A URL-preview feature is redirected toward an internal management endpoint.Allowlist destinations and protocols; block internal and metadata ranges; validate redirects and resolved addresses; restrict network egress.
API8:2023Security MisconfigurationOWASP source ↗Insecure API infrastructure settings, debug features, permissive CORS, unnecessary methods, weak transport settings, or verbose errors create exposure.A forgotten diagnostic route exposes internal service details in production.Harden gateways and services; disable debug and unused methods; configure TLS and CORS correctly; continuously assess deployments.
API9:2023Improper Inventory ManagementOWASP source ↗Unknown hosts, undocumented endpoints, obsolete versions, and unmanaged data flows leave APIs outside normal ownership, protection, and retirement processes.A deprecated API version remains reachable with weaker authentication than the current service.Maintain API and data-flow inventories; assign owners; document versions and exposure; discover shadow APIs; retire unused endpoints.
API10:2023Unsafe Consumption of APIsOWASP source ↗Applications trust third-party API responses too much. Malicious or compromised upstream data can exploit downstream logic, parsers, redirects, and resource handling.A partner response contains a malicious URL that the application follows automatically.Validate upstream data as untrusted; enforce schemas, timeouts and size limits; constrain redirects; assess provider security.

Authorization reminder: BOLA = which object; BOPLA = which properties; BFLA = which function. Token validation alone answers none of these completely.

03

Model inputs, outputs, data, retrieval and application agency.

2026OWASP list ↗

What can influence the model, what can leak, and what can its output trigger?

Risk / official identifierSummary · what it coversIllustrative exampleKey controls
LLM01:2026Prompt InjectionOWASP source ↗Direct prompts or instructions hidden in retrieved content steer the model away from its intended task. Text, images, documents, and tool results can carry the instructions.A retrieved support article tells an assistant to expose confidential conversation content.Separate trusted instructions from external content; constrain tools and data access; validate actions outside the model; test indirect injection.
LLM02:2026Sensitive Information DisclosureOWASP source ↗The model or application reveals confidential data from training, context, retrieval, or connected systems. Leakage may occur through answers or downstream output paths.An assistant’s response includes confidential details from another user’s document.Minimize sensitive context; enforce source permissions; redact and monitor outputs; isolate users and tenants; keep credentials out of prompts.
LLM03:2026Excessive AgencyOWASP source ↗An LLM application has more functionality, permissions, or autonomy than its task requires, amplifying the harm from model errors or manipulated inputs.An email summarizer also has permission to send messages and delete the mailbox.Expose narrowly scoped tools; use least privilege and user-scoped access; require approval for consequential actions; enforce policies in code.
LLM04:2026Supply ChainOWASP source ↗Compromised models, datasets, libraries, adapters, and other third-party components undermine the integrity of the LLM application and its deployment.A downloaded model artifact or supporting package includes a malicious payload.Verify provenance and integrity; inventory AI components; pin versions; assess suppliers; scan dependencies and use safe artifact formats.
LLM05:2026Data and Model PoisoningOWASP source ↗Attackers manipulate training, fine-tuning, or model-development data and artifacts to introduce biased behavior, hidden triggers, or persistent backdoors.Poisoned fine-tuning examples make a model respond unsafely to a specific trigger.Control dataset access and lineage; validate data and models; review changes; test for backdoors and behavioral regressions.
LLM06:2026Unbounded ConsumptionOWASP source ↗Uncontrolled inference and related workloads exhaust resources, degrade availability, or inflate costs. Repeated requests and expensive operations can turn an application into a financial liability.Automated queries repeatedly trigger the most expensive available generation workflow.Set token, request, concurrency and workload limits; enforce cost ceilings; monitor usage; constrain execution time and resource access.
LLM07:2026MisinformationOWASP source ↗Incorrect or misleading model output appears credible and is trusted. Hallucinations, weak grounding, incomplete answers, and overreliance can lead to harmful decisions.An assistant confidently cites a nonexistent policy and a reviewer acts on it.Ground answers in authoritative sources; verify claims and citations; test accuracy; communicate uncertainty; require expert review where needed.
LLM08:2026Hidden Context ExposureOWASP source ↗Internal instructions, tool schemas, or operational context are extracted or inferred, revealing security-relevant implementation details. This expands the earlier System Prompt Leakage category.A user reconstructs hidden tool definitions and internal approval criteria.Assume model-visible context can leak; exclude secrets; enforce authorization and critical policy in independent systems.
LLM09:2026Vector and Embedding WeaknessesOWASP source ↗Weaknesses in vector-based retrieval and embedding handling enable unauthorized data exposure, manipulated retrieval, and disclosure of information represented by embeddings.A shared retrieval index returns confidential content from the wrong tenant.Apply retrieval access controls and tenant isolation; validate data sources; protect embeddings; monitor indexing and retrieval behavior.
LLM10:2026Improper Output HandlingOWASP source ↗Generated output reaches browsers, interpreters, or downstream systems without appropriate validation and sanitization, enabling conventional injection and execution vulnerabilities.Model-generated markup executes in a browser or generated text becomes a shell command.Treat outputs as untrusted; encode for the destination; use parameterized APIs; validate schemas; isolate any code execution.

2026 IDs and names follow the published OWASP PDF. Supporting 2025 guidance remains relevant to unchanged concepts; do not reuse its risk numbers for this edition.

04

Autonomous goals, tools, identities, memory and coordination.

2026OWASP list ↗

Can autonomous actions stay within approved intent and authority?

Risk / official identifierSummary · what it coversIllustrative exampleKey controls
ASI01Agent Goal HijackOWASP source ↗Attacker-controlled inputs redirect an agent’s objective, planning, or action selection.A document diverts an expense-review agent into exporting employee records.Bind actions to approved intent; check scope at execution; constrain privileges.
ASI02Tool Misuse and ExploitationOWASP source ↗An agent uses legitimate tools in unsafe ways or harmful combinations.A support agent chains permitted export and messaging tools to leak records.Validate tool arguments and purpose; constrain combinations, destinations and action budgets.
ASI03Identity and Privilege AbuseOWASP source ↗Delegation, credentials, or inherited trust enable unauthorized access and privilege escalation.A low-privilege worker persuades an administrator agent to act on its behalf.Use distinct agent identities, scoped delegation and short-lived credentials; reauthorize actions.
ASI04Agentic Supply Chain VulnerabilitiesOWASP source ↗Compromised tools, agent components, or dependencies enter an agent’s trusted execution environment.A counterfeit MCP integration impersonates an approved connector.Maintain approved registries; verify provenance; pin versions; review dynamic component changes.
ASI05Unexpected Code Execution (RCE)OWASP source ↗Generated or injected code executes outside the intended safe workflow.A troubleshooting agent runs an unreviewed repair script from retrieved content.Use constrained execution, strong sandboxing and restricted egress; validate execution requests.
ASI06Memory & Context PoisoningOWASP source ↗Corrupted stored knowledge or working context alters later agent decisions and behavior.A false authorization exception is remembered and reused in a later session.Control memory writes; retain provenance; isolate sessions; validate retrieval; support rollback.
ASI07Insecure Inter-Agent CommunicationOWASP source ↗Weak message authentication, integrity, confidentiality, or authorization enables deception between agents.A forged completion message causes another agent to release a transaction.Authenticate peers; protect message integrity and freshness; authorize each delegated request.
ASI08Cascading FailuresOWASP source ↗Errors or malicious signals propagate across agents and amplify their impact.A faulty inventory estimate triggers purchasing, billing, and fulfillment errors.Validate handoffs; isolate failures; bound retries; use circuit breakers and recovery checkpoints.
ASI09Human-Agent Trust ExploitationOWASP source ↗Convincing agent output manipulates people into approving or accepting unsafe actions.A reassuring summary conceals the actual scope of a destructive change.Show exact effects and evidence; independently verify high-impact approvals; reduce approval fatigue.
ASI10Rogue AgentsOWASP source ↗Agents depart from intended behavior through misalignment, concealment, or self-directed actions.An agent continues changing records after its approved task has ended.Monitor behavior; enforce external limits; revoke credentials; provide reliable shutdown and rollback.

These risks extend into planning, execution and coordination. The same incident can map to several categories; the IDs are not mutually exclusive failure modes.

05

Reusable instruction packages, scripts and workflow behavior.

V1 (Aug 2026) · IncubatorOWASP list ↗

Can this skill be trusted throughout installation, execution, updates and reuse?

Risk / official identifierSummary · what it coversIllustrative exampleKey controls
AST01Malicious SkillsOWASP source ↗A skill is intentionally harmful despite appearing useful. Malicious behavior may live in natural-language instructions, scripts, bundled resources, or combinations of these elements.A report-generation skill quietly instructs the agent to upload local credentials.Review the complete package; verify publisher and provenance; use behavioral checks; restrict secrets access and outbound destinations.
AST02Supply Chain CompromiseOWASP source ↗A registry, maintainer account, dependency, or distribution channel is compromised, allowing an attacker to deliver altered skills through an apparently trusted source.A trusted publisher’s account is taken over and distributes a modified skill.Protect publication accounts; verify package signatures and provenance; pin dependencies; monitor registries; support revocation and quarantine.
AST03Over-Privileged SkillsOWASP source ↗A skill receives broader file, network, shell, tool, or memory permissions than its purpose requires, expanding the damage from misuse or compromise.A formatting skill receives access to the entire home directory and unrestricted network egress.Declare minimal permissions; enforce them at runtime; isolate credentials; restrict paths, tools and destinations; review privilege changes.
AST04Insecure MetadataOWASP source ↗Missing, misleading, or unsafe manifest and configuration metadata undermines trust decisions or enables dangerous loading and parsing behavior.A skill understates its capabilities or uses unsafe configuration parsing to trigger behavior.Validate schemas; use safe parsers; verify publisher identity; compare declared permissions and dependencies with actual behavior.
AST05Untrusted External InstructionsOWASP source ↗A skill imports behavior from external pages, documents, or other mutable sources that were not included in the original trust and review decision.An approved skill follows a linked guide that an attacker later modifies.Inventory instruction sources; pin or snapshot reviewed content; rescan changes; keep external instructions subject to policy and isolation.
AST06Weak IsolationOWASP source ↗Skills run with inadequate separation from the host, other tasks, sensitive files, or network services. A compromised skill can reach beyond its intended workspace.A skill’s helper process can read unrelated project secrets on the same host.Use hardened sandboxes; restrict filesystem mounts, egress and process capabilities; separate tasks and credentials; verify effective containment.
AST07Update DriftOWASP source ↗Skill code, dependencies, configuration, or runtime behavior changes after approval, so the deployed version no longer matches what was reviewed.An automatic update adds new network behavior without a fresh review.Pin immutable versions and hashes; review changes and permission differences; test upgrades; retain rollback and timely patching processes.
AST08Poor ScanningOWASP source ↗Incomplete or simplistic assessment misses malicious instructions and behavior. Checking code signatures alone does not adequately assess natural-language workflows or runtime interactions.A scanner approves clean scripts while overlooking harmful instructions in the skill description.Combine static, semantic and behavioral review; inspect all resources and dependencies; scan at publication, installation and update.
AST09No GovernanceOWASP source ↗Skills operate without an owned inventory, approval lifecycle, accountability, monitoring, or revocation process, allowing unmanaged adoption and persistent exposure.Teams install untracked skills with no owner or process to remove a compromised version.Maintain an approved catalog; assign owners and risk tiers; record actions; periodically review access; exercise incident response and revocation.
AST10Cross-Platform ReuseOWASP source ↗Porting a skill between ecosystems changes how permissions, metadata, or execution boundaries are interpreted, potentially weakening security assumptions that held on the original platform.A migrated skill loses its original destination restrictions and runs with broader access.Revalidate permissions and sandbox behavior on each platform; preserve provenance and security metadata; test ports before deployment.

Skills package reusable behavior and may include instructions, scripts and resources. Security metadata helps express intent; the runtime must actually enforce the declared restrictions.

06

Model Context Protocol servers, tools, credentials and shared context.

2025 · BetaOWASP list ↗
Risk / official identifierSummary · what it coversIllustrative exampleKey controls
MCP01:2025Token Mismanagement & Secret ExposureOWASP source ↗Credentials leak through configuration, logs, prompts or tool payloads, letting another party impersonate a trusted client or server.A debug trace records a reusable repository token.Keep secrets outside model context; redact logs; use scoped, short-lived tokens and managed secret storage.
MCP02:2025Privilege Escalation via Scope CreepOWASP source ↗Tool permissions accumulate beyond the original task, increasing the damage possible from a compromised session or manipulated agent.A read-only assistant gradually receives deployment and account-management privileges.Define explicit permission budgets; expire temporary grants; review entitlements and alert on scope changes.
MCP03:2025Tool PoisoningOWASP source ↗Malicious tool descriptions or metadata influence tool selection and behavior before a tool is even executed.A tool description tells the assistant to disclose sensitive context when calling it.Review tool definitions; pin approved versions; detect metadata changes; enforce action and data policies outside the model.
MCP04:2025Software Supply Chain Attacks & Dependency TamperingOWASP source ↗Compromised MCP servers, packages or dependencies introduce malicious code into otherwise trusted integrations.An updated server package steals credentials at startup.Approve sources; verify provenance and integrity; pin dependencies; scan and isolate server execution.
MCP05:2025Command Injection & ExecutionOWASP source ↗Untrusted tool arguments become executable shell commands or code because the server builds unsafe commands.A file-processing tool concatenates an unvalidated filename into a shell command.Use structured APIs and argument arrays; validate inputs; avoid shell interpolation; sandbox execution with least privilege.
MCP06:2025Intent Flow SubversionOWASP source ↗Instructions hidden in resources or tool results redirect the agent’s plan away from the user’s request. Formerly “Prompt Injection via Contextual Payloads”.A retrieved status report instructs the assistant to export unrelated private records.Treat retrieved content as data; constrain permitted actions; independently check tool calls against user intent; approve consequential actions.
MCP07:2025Insufficient Authentication & AuthorizationOWASP source ↗Weak identity checks or missing resource and operation permissions allow unauthorized clients to invoke tools or access data.A server trusts any caller with network access to run an administrative tool.Authenticate clients; validate token issuer, audience and expiry; authorize each tool and resource request; isolate tenants.
MCP08:2025Lack of Audit and TelemetryOWASP source ↗Missing or fragmented records prevent reconstruction of who invoked a tool, what it accessed and what happened.A sensitive export occurs without an attributable tool-call record.Record caller, tool, target, decision and outcome; correlate sessions; protect logs; redact secrets and alert on unusual activity.
MCP09:2025Shadow MCP ServersOWASP source ↗Unregistered or unmanaged servers connect to agents outside normal inventory, security review and lifecycle controls.A developer adds an unofficial connector that quietly retains confidential tool responses.Maintain an approved server inventory; enforce connection policies; discover unmanaged endpoints; assign owners and retirement dates.
MCP10:2025Context Injection & Over-SharingOWASP source ↗Untrusted or excessive context crosses tool, session or user boundaries, enabling manipulation and disclosure beyond the task’s needs.A connector receives the entire conversation when it only needs a document identifier.Minimize tool payloads; isolate sessions and tenants; label provenance; filter sensitive data and enforce destination-specific access.

Beta list. MCP06 was renamed “Intent Flow Subversion” in the project source on 12 January 2026; the rendered owasp.org project page still shows the old name, “Prompt Injection via Contextual Payloads”.

07

Service accounts, workload identities, tokens and machine-to-machine access.

2025 · IncubatorOWASP list ↗
Risk / official identifierSummary · what it coversIllustrative exampleKey controls
NHI1:2025Improper OffboardingOWASP source ↗Service accounts and integration credentials remain active after their workload, owner or business purpose has gone.An abandoned test integration still has access to production.Inventory identities and owners; disable unused accounts; transfer ownership and rotate credentials during offboarding.
NHI2:2025Secret LeakageOWASP source ↗Machine credentials escape through code, logs, developer devices or third-party systems and can be reused by attackers.A database password is committed to a repository.Scan for secrets; store them centrally; redact outputs; revoke exposed credentials; prefer ephemeral workload credentials.
NHI3:2025Vulnerable Third-Party NHIOWASP source ↗External applications, extensions or services can misuse entrusted identities or expose them when compromised.A compromised IDE extension steals a cloud integration token.Assess integrations; grant minimal scopes; monitor third-party use; review consent and revoke unnecessary access.
NHI4:2025Insecure AuthenticationOWASP source ↗Weak or poorly validated machine authentication makes it possible to forge or impersonate a workload’s identity.A service accepts a workload token without checking its intended audience.Use robust workload identity; validate claims and trust chains; avoid weak shared credentials; secure token issuance.
NHI5:2025Overprivileged NHIOWASP source ↗Non-human identities have access to more resources or operations than their workloads require.A reporting job can delete the source database.Grant narrowly scoped roles; separate duties; review effective permissions; remove unused grants and constrain privilege elevation.
NHI6:2025Insecure Cloud Deployment ConfigurationsOWASP source ↗Overly broad deployment trust settings let an unintended workload obtain cloud credentials or assume a privileged role.A deployment role trusts tokens from every repository in an organization.Restrict issuer, audience, subject and environment claims; protect deployment branches; review federation and role trust policies.
NHI7:2025Long-Lived SecretsOWASP source ↗Persistent keys and tokens remain useful for an extended period after theft or accidental disclosure.A years-old automation key continues to authenticate without rotation.Prefer short-lived tokens and managed identities; automate rotation; enforce expiry and test prompt revocation.
NHI8:2025Environment IsolationOWASP source ↗Insufficient separation between development, testing and production lets a lower-trust environment reach sensitive systems.A test runner holds credentials accepted by production services.Separate identities, secrets and trust relationships by environment; restrict network paths; prohibit cross-environment credential reuse.
NHI9:2025NHI ReuseOWASP source ↗Several workloads share one identity, expanding its exposure and obscuring the source of individual actions.Multiple unrelated jobs all authenticate with the same service account.Assign each workload a distinct identity; scope access per purpose; track ownership and attribute activity to the originating workload.
NHI10:2025Human Use of NHIOWASP source ↗People use service identities for interactive work, bypassing user-specific controls and weakening accountability.An administrator logs in with a shared automation credential.Require named human identities and MFA; restrict service accounts to workloads; audit exceptions and separate emergency access.

NHI1–NHI10 follow the 2025 list. NHI8 addresses failures of environment isolation.

K08Cluster To Cloud Lateral MovementOWASP source ↗A compromised pod or node can obtain cloud identities and move into the surrounding cloud environment.A workload accesses node metadata and obtains an overly powerful cloud role.Use scoped workload identity; restrict metadata access; minimize node roles; audit cloud trust and cluster-to-cloud paths.

K10Inadequate Logging And MonitoringOWASP source ↗Missing cluster audit, workload and runtime signals prevent detection and investigation of malicious activity.Unexpected secret reads and new privileged pods produce no alert.Enable appropriate API audit logging; centralize protected telemetry; monitor sensitive actions and runtime changes; test alert handling.

Training data, model privacy, adversarial inputs and model integrity.

2023 · Draft v0.3OWASP list ↗
Risk / official identifierSummary · what it coversIllustrative exampleKey controls
ML01:2023Input Manipulation AttackOWASP source ↗Adversarially crafted inference inputs cause incorrect predictions while appearing acceptable to ordinary validation.A subtly modified image is misclassified by a vision model.Validate inputs; evaluate adversarial robustness; monitor outliers; add independent checks for consequential model decisions.
ML02:2023Data Poisoning AttackOWASP source ↗Manipulated training samples or labels teach the model unwanted behavior or introduce a backdoor.Maliciously relabelled examples degrade a classifier’s ability to detect abuse.Track dataset provenance; restrict modifications; validate labels and distributions; evaluate against a clean, independently held test set.
ML03:2023Model Inversion AttackOWASP source ↗Model access or prediction responses reveal information about sensitive inputs or learned training-data characteristics.Repeated queries help reconstruct sensitive attributes represented in a model.Limit exposed prediction detail and query access; evaluate privacy leakage; use suitable privacy-preserving training and monitor extraction attempts.
ML04:2023Membership Inference AttackOWASP source ↗An attacker infers whether a particular record was included in training, which can reveal sensitive participation or association.Prediction behavior suggests that an individual’s record belongs to a private dataset.Test membership leakage; reduce overfitting; limit unnecessary confidence outputs; consider differential privacy and constrain query access.
ML05:2023Model TheftOWASP source ↗Unauthorized access or reverse engineering copies model parameters or proprietary model functionality.An exposed model registry allows valuable weights to be downloaded.Protect model storage and endpoints; restrict exports; encrypt transfers; monitor unusual access and bulk queries; track model provenance.
ML06:2023AI Supply Chain AttacksOWASP source ↗Compromised libraries, model artifacts or data sources enter the ML system through external dependencies.A downloaded model package executes malicious code during loading.Approve sources; verify signatures and hashes against trusted provenance; scan dependencies; use safe artifact formats and isolated loading.
ML07:2023Transfer Learning AttackOWASP source ↗Malicious behavior embedded in a source model or training process carries into a model adapted for another task.A reused pretrained model retains a hidden trigger after fine-tuning.Validate source-model provenance; assess transferred behavior and triggers; secure fine-tuning data; isolate training and deployment.
ML08:2023Model SkewingOWASP source ↗Manipulating training-data distribution or feedback loops gradually shifts model behavior toward an attacker’s preferred outcomes.Fabricated feedback causes a fraud model to treat suspicious activity as normal.Authenticate feedback; limit contributor influence; monitor distribution shifts; validate updates against trusted data before promotion.
ML09:2023Output Integrity AttackOWASP source ↗Predictions are altered after inference or along the path to a consuming application, corrupting downstream decisions.A compromised intermediary replaces an alert score with a benign value.Authenticate output channels; protect response integrity; validate schemas and provenance; preserve tamper-evident audit records.
ML10:2023Model PoisoningOWASP source ↗Direct changes to model parameters or artifacts introduce unwanted behavior independently of ordinary data collection.An attacker replaces stored weights with a backdoored model.Restrict parameter and registry writes; verify artifact integrity before serving; require controlled promotion and keep trusted rollback versions.
